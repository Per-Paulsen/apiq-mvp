# Epic 22 — Score Badges + Markdown Findings Export

> Two distribution-loop surfaces bundled because both ride the spec-detail Export/Share dropdown UX and both render derived spec-data: (a) hosted SVG quality-score badge at `apiq.dev/badge/<token>.svg` (codecov-style passive viral), (b) markdown findings export for Slack/PR-comments + AI-Roundtrip prompts.
> Upstream: [`prd-launch.md`](../prd-launch.md) §3 "Distribution & Viral block" rows "Score Badges" + "Markdown Findings Export", §2 exit options 2 + 4, [`specs/brainstorming-launch.md`](./brainstorming-launch.md) §"Score Badge", §"Markdown Findings Export".

## Scope

### Score Badge

- New `Spec.badgeToken` column (nullable, unique, 22-char base62). Migration: `add_badge_token`.
- Server action `enableBadgeAction({ specId })` generates token if not set; returns the badge URL.
- Server action `disableBadgeAction({ specId })` sets `badgeToken = null`.
- New Edge route `src/app/badge/[token]/route.ts`:
  - Looks up `Spec` by `badgeToken`. Returns 404 SVG fallback if not found.
  - Returns dynamic SVG with content-type `image/svg+xml`.
  - `Cache-Control: public, max-age=300, stale-while-revalidate=3600` (5 min edge + 1 h SWR per `brainstorming-launch.md`).
- Two SVG styles via `?style=` query param:
  - **Default** (no param) — codecov-shield-style: `[apiq | 87]` rectangle ~120×20 px. Color-banded by score (red <60, amber 60–79, emerald ≥80).
  - **Ring** (`?style=ring`) — bigger circular SVG ~80×80 px with score-ring + number inside.
- Spec-deletion fallback: badge token persists but lookup fails → return generic `[apiq | n/a]` grey SVG with `Cache-Control: public, max-age=86400` (24 h cached error).

### Score Badge UI integration

- Spec-Detail Share-dropdown (Epic 19) gets two new entries:
  - **Generate badge** — calls `enableBadgeAction`, copies badge-URL + markdown-snippet (`![apiq](https://apiq.dev/badge/<token>.svg)`) to clipboard.
  - **Disable badge** (only if badge enabled) — confirm modal → `disableBadgeAction`.

### Markdown Findings Export

- Server action `exportFindingsMarkdownAction({ specId, filter })` in `src/app/(app)/specs/[specId]/actions.ts`:
  - Filter param: `'open_critical_high' | 'open_all' | 'applied_only' | 'all'`. Default: `'open_critical_high'`.
  - Loads spec + findings matching filter.
  - Renders markdown per the structure in §"Output structure".
  - Returns `{ filename: '<slug>-findings.md', content }`.
- UI: Spec-Detail header gets a "Export findings" dropdown next to existing JSON/YAML buttons:
  - Default option: *"Export markdown (open critical+high)"*.
  - Sub-menu: 4 filter options.
- CLI / MCP wrap this via `apiq.export({ format: 'markdown' })` and `apiq check --markdown`.

### Output structure (markdown)

```markdown
# {SpecName} — apiq Findings

Quality Score: **{score}/100** ({nCritical} critical · {nHigh} high · {nMedium} medium · {nLow} low)

Generated: {timestamp ISO}

## Critical findings ({n})

### `{METHOD} {path}` — {title}

{narration}

**Why this matters:** {rationale}

<details>
<summary>Suggested patch (JSON Patch RFC 6902)</summary>

\`\`\`json
{patchOps as pretty JSON}
\`\`\`

</details>

---

(... more findings)

## High findings ({n})

(... etc)

## Medium findings ({n})

(... etc)

## Low findings ({n})

(... etc)

---

_Generated by apiq.dev — quality gate for OpenAPI specs_
```

PatchOps wrapped in `<details>` / `<summary>` collapsed-by-default; works on GitHub-flavored Markdown (PR comments) and degrades gracefully on Slack (renders fully expanded).

### `cycle-marker` handling

- `restoreCycleRefs` (Epic 14) called on the rendered patches' targets if they reference cycle-marked schemas. No raw `#cyclic` markers in markdown output.

## Acceptance criteria

1. `Spec.badgeToken` column added via migration.
2. `enableBadgeAction`, `disableBadgeAction` server actions in place.
3. Edge route `/badge/[token]/route.ts` returns:
   - Default codecov-shield style ~120×20 px when no `style` query param.
   - `?style=ring` returns ~80×80 px circular SVG.
   - 24 h-cached `[apiq | n/a]` grey SVG when token unknown.
4. Score color-bands match `prd-decisions.md` (red <60, amber 60–79, emerald ≥80).
5. Cache headers: 5 min max-age + 1 h SWR.
6. Spec-Detail Share-dropdown has Generate / Disable badge entries; on generate, URL + markdown-snippet copied to clipboard.
7. `exportFindingsMarkdownAction` accepts 4 filter options, returns `{ filename, content }`.
8. Markdown output matches the structure in §"Output structure" (verified by snapshot test).
9. PatchOps wrapped in collapsible `<details>` blocks.
10. Cycle-marker-restoration applied to patch targets (no `#cyclic` strings in markdown).
11. Spec-Detail "Export findings" dropdown in header with 4 filter options.
12. CLI `apiq check --markdown` and MCP `apiq.export({ format: 'markdown' })` use this same action.
13. Vitest tests pass; markdown snapshot fixture committed.

## Out of scope

- GitHub Action that auto-fails CI when badge score drops — v1.1.
- Other badge formats (PNG, JSON, plastic-style) — v1.1 if requested.
- Markdown-export for a single finding (currently only spec-wide) — v1.1.
- HTML export of findings — out of scope; markdown is sufficient for both human + AI consumption.
- Badge-tracking analytics (page views per badge) — Epic 26 PostHog covers if user opts in to the page view event.
- Multi-language markdown — English only in v1.

## Domain terms

- **Score badge** — the public hosted SVG showing the spec's quality score; embeddable as `![apiq](url)` in any markdown surface.
- **Badge token** — 22-char base62 string distinct from share token; opt-in per spec.
- **Codecov-shield style** — the rectangular `[label | value]` SVG style popularized by Codecov / Coveralls.
- **Markdown findings export** — markdown rendering of findings + score for share-out (Slack, PR, AI roundtrip).
- **AI-Roundtrip** — feeding the markdown output back into Cursor / Claude Code with prompt *"AI, regenerate the spec with these fixes"*.

## Open questions

- Should badge token be re-generatable? Recommendation: yes — `enableBadgeAction` overwrites if already set, returns the new URL. Old URL becomes 404. Use case: rotating after accidental exposure.
- Badge SVG fonts: avoid web-fonts (slow + privacy). Use system-stack `font-family="system-ui, -apple-system, sans-serif"` rendered text. Compare against codecov.io's actual approach during impl.
- Markdown-export filename: include timestamp or just slug? Recommendation: `<slug>-findings.md` without timestamp (filesystems dedupe by save dialog; users can rename).
- Should the "Export findings" dropdown also include "Export YAML" / "Export JSON" entries (consolidate Epic 08 buttons)? Recommendation: keep YAML/JSON separate (header-buttons) from "Export findings" dropdown (spec-content vs findings are different deliverables). Re-evaluate if header gets crowded.
