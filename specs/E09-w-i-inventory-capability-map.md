### I1 — `scripts/spike/eval/build-inventory.ts`

Scannt codebase deterministically + extrahiert structured data.

**Sub-extracts:**
- **YAML-rules:** alle 12 yamls in `scripts/spike/deterministic/rules/` → Liste of `{ name, file, patternId, severity, recommended, given, function, lenses, defectClass, codegenTargets, agentReadinessImpact, autoFixSafe, regulatoryMapping, ... alle apiq-meta-Felder }`
- **Module-classes:** alle in `scripts/spike/deterministic/modules/` → `{ file, exports, patternIds_handled, wired_in_index_ts, sample_findingsExpected }` (parsed via TypeScript-AST mit `ts-morph` ODER regex falls AST-overkill)
- **Walkers/Aggregators:** alle in `scripts/spike/deterministic/aggregators/` → analog
- **Classifiers:** alle in `scripts/spike/deterministic/classifiers/` → analog
- **Custom-Functions:** alle in `scripts/spike/deterministic/spectral-functions/` (inkl. `_helpers/`) → `{ file, exports, used_by_yaml_rules: [yaml-rule-names die das function-name referenzieren] }`
- **Test-files:** alle `scripts/spike/__tests__/**/*.test.ts` + `src/__tests__/**/*.test.ts` → `{ file, target_module: inferred-from-imports, test_count, describe_blocks: [titles] }`
- **Patterns.json substrate:** alle 972 patterns → mapped per patternId (zur Cross-Reference)
- **Apiq-meta-Schema-fields:** parse `infra/severity-schema.ts` → list of all required + optional fields per RuleMetadata-schema

**Output:** 
- `scripts/spike/eval/inventory.json` (gitignored, regenerable, ~500-1000KB JSON)
- `scripts/spike/eval/INVENTORY.md` (committed, auto-generated markdown-view; structure: per-section table per category mit deeplinks zu Code-Files)

**Header-Banner in INVENTORY.md:** "Auto-generated by `npm run build-inventory`. Do not edit manually. Last-regenerated: <ISO-timestamp>. Run `npm run build-inventory` after any code-change to deterministic/ subtree."

### I2 — `scripts/spike/eval/build-coverage-map.ts`

Läuft EINMAL `runDeterministicLayer` auf alle 4 Reference-Specs (~45min sequenziell) + outputs structured coverage-data.

**Sub-extracts:**
- **Per detector:** `{ detectorId, layer, fires_on_specs: ['stripe-full', ...], total_findings_count, finding_count_per_spec: { 'stripe-full': N, ... } }`
- **Per Pattern-ID:** `{ patternId, detector_ids: [...], fires_on_specs: [...] }` (resolves Pattern-ID → detector-id chain via apiq-meta lookup)
- **Per Lens:** `{ lens, total_patternIds, total_yaml_rules_active, total_modules_active, fires_on_specs_aggregate }`
- **Per Spec:** `{ spec_name, total_findings, per_detector_breakdown, per_layer_breakdown, runtime_ms, top_10_detectors_by_count }`
- **Untested-detectors:** detectors die existieren aber auf 0 von 4 Specs fire → drift-class "dead-code-suspicion"

**Output:** 
- `scripts/spike/eval/coverage.json` (gitignored, regenerable, ~200-500KB)
- `scripts/spike/eval/COVERAGE.md` (committed view)

**Runtime-Considerations:** 
- 4-Spec-Run sequenziell ~45min (stripe-full 23min + github-rest 15min + pagerduty 5min + dnd5e <1min)
- Build-script soll progress-output emittieren (welche Spec gerade läuft + ETA)
- Persist intermediate per-spec-results so dass Re-Runs partielle Daten reusen können wenn z.B. github-rest crashed

**Header-Banner in COVERAGE.md:** Last-regenerated + reference-spec-versions (Git-SHA der `openapi-examples/*/spec.json` Files).

### I3 — Cross-References + Drift-Detection

Inventory + coverage cross-correlated zu actionable insights.

**Cross-References:**
- **Per Lens cross-reference:** "Lens-1 (Threat) wird von 60 yaml-rules + 4 modules + 8 functions abgedeckt; fires-on-spec aggregate: stripe-full × N detectors, github-rest × M, etc."
- **Per Pattern-Family:** "RFC2-* family: 122 patterns in patterns.json, 47 als yaml-rules realized, 6 als modules, 2 als walkers, fires-on summary"
- **Per Welle-Origin:** "Welle D contributed 171 P3 yaml-rules + 90 functions + 3 walkers; Welle D2 contributed 12 yaml-rules + 11 functions; etc." (parsed aus apiq-meta `source` field oder Welle-tagging)

**Drift-Detection-Klassen:**
- **drift-class-1 (substrate-only):** patternId in patterns.json existiert, aber 0 detectors handelt es → "Stage-B-territory" oder "vergessen zu implementieren"
- **drift-class-2 (dead-code):** detector existiert, fires aber auf 0 von 4 Specs → "missing-fixture" oder "broken-detection"
- **drift-class-3 (orphan-module):** module-class file in `modules/` aber nicht wired in `modules/index.ts` → "WIP" oder "intentionally-orphaned" (Beispiel: spec-diff.ts)
- **drift-class-4 (function-binding-broken):** YAML-rule referenziert function-name die NICHT in `APIQ_CUSTOM_FUNCTIONS` exportiert ist → "broken rule"
- **drift-class-5 (claimed-vs-actual-mismatch):** parse Plan-Doc + CLAUDE.md für concrete-claims (z.B. "354 yaml-rules", "127 functions", "27/28 Springer-Delphi covered") + verify gegen inventory.json → flag mismatches mit doc-line-references

**Output:** 
- `scripts/spike/eval/CROSS-REFERENCES.md` (committed)
- `scripts/spike/eval/DRIFT-REPORT.md` (committed)

### I4 — Test-Coverage-Map

Wie I2/I3 aber für tests.

**Sub-extracts:**
- Pro test-file: welche detector(s) wird getestet (parsed via imports + `describe` titles + spectral-runner-references)
- Pro detector: welche test-files covered es
- Pro yaml-rule: welche tests covered es (via rule-name-substring-match in test-titles)
- **Untested-detectors:** detector existiert + fires (per coverage.json) aber kein test-file referenziert es → coverage-gap
- **Test-orphans:** test-file referenziert detector der nicht mehr existiert → cleanup-candidate

**Output:** `scripts/spike/eval/TEST-COVERAGE.md` (committed)

### I5 — API-Surface-Export

Parse `index.ts`-Files + cross-reference Imports.

**Sub-extracts:**
- Pro `index.ts` (deterministic/index.ts + sub-folder index.ts): exports + welche files importieren sie (cross-repo grep)

**Output:** `scripts/spike/eval/API-SURFACE.md` (committed)

### I6 — CI-Integration

**workflow 1 — `inventory-drift.yml` (per-PR):**
- Trigger: PR opened/updated, push to main
- Steps:
  1. Checkout + npm install
  2. Run I1 (build-inventory) + I3 (cross-refs + drift) — these are fast (~1-2min)
  3. Diff committed `INVENTORY.md` / `CROSS-REFERENCES.md` / `DRIFT-REPORT.md` vs newly-generated
  4. **Fail wenn drift exists** → comment-on-PR mit "run `npm run build-inventory` und commit"
  5. Skip I2 (coverage) — too slow für per-PR (~45min)

**workflow 2 — `coverage-nightly.yml` (cron):**
- Trigger: nightly cron `0 3 * * *` + manual workflow_dispatch
- Steps:
  1. Run I2 (build-coverage-map) — ~45min
  2. Diff committed `COVERAGE.md` vs newly-generated
  3. If diff: open PR mit updated COVERAGE.md (peter-evans/create-pull-request@v6)
  4. If no-diff: noop

**Pre-commit-hook (optional, opt-in):**
- `.git/hooks/pre-commit` script (NOT committed; instructions in INVENTORY.md): runs I1 + I3 locally + warns wenn drift unstaged

**npm scripts (committed in package.json):**
- `npm run build-inventory` → tsx I1
- `npm run build-coverage` → tsx I2 (langsam, manual)
- `npm run cross-refs` → tsx I3
- `npm run inventory-all` → I1 + I3 + I4 + I5 (everything fast)

## Out of scope

- **Drift-Fixes selbst:** Welle I produces DRIFT-REPORT.md, fixt aber nicht jeden Drift sofort (würde Welle-Scope sprengen). Per "niemals defern" werden fix-able drifts in einem Resolution-Pass-Commit nach Welle-I-Main gefixt; nicht-trivial fixes als separate Patches dokumentiert.
- **Welle-T2 Snapshot-Tests:** Test-Coverage-Map (I4) identifiziert was getestet sein sollte; T2 implementiert die fehlenden Snapshot-Tests. T2 territory.
- **Welle-Doc Documentation:** I generiert auto-files, nicht human-curated docs (Architecture-Diagram, Contributor-Guide). Doc territory.
- **Welle-V Cross-Linter-Validation:** I dokumentiert apiq's eigene capability; V vergleicht gegen Vacuum/Redocly/IBM/OWASP. V territory.
- **Real-time/streaming inventory updates:** I generiert artifacts on-demand (manual + CI-cron); nicht real-time-watch oder file-system-event-driven.

## Domain terms

- **Inventory:** static-analysis-extraction von "was existiert wo" — yaml-rules, modules, walkers, classifiers, functions, tests, patterns. Code-state als data.
- **Capability-Map / Coverage-Map:** runtime-extraction von "was fires wo" — per-detector + per-spec + per-Pattern-ID. Empirical fire-data als data.
- **Drift:** divergence zwischen erwartetem state (in docs claimed) und actual state (im code/runtime). 5 drift-classes (substrate-only / dead-code / orphan-module / function-binding-broken / claimed-vs-actual-mismatch).
- **Authoritative single-source-of-truth:** Inventory + Coverage sind die source-of-truth ab Welle I. Plan-Doc / CLAUDE.md / brainstorm-files sind narrative-doku, NICHT capability-source.
- **Auto-generated markdown-view:** Inventory/Coverage werden zu human-readable markdown gerendert + committed (für Welle-Spec-Authoring + GitHub-browseable). JSON-data ist gitignored (regenerable).
- **CI-gate:** PR-workflow validates dass committed INVENTORY.md / CROSS-REFERENCES.md / DRIFT-REPORT.md aktuell sind vs code-state. Verhindert silent drift.
